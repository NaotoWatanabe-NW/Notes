# 0005 著者の分け方の見直し（`・` で分ける・イニシャルと出版社の名前を著者にしない）

## 1. 状態・日付

- 状態: 実装済み（2026-10-14）
- 日付: 2026-10-14
- 関連: [0002 著者ノート](0002-author-notes.md) §3 決定2（著者の分け方。**この設計書で変える**）・§5.2〜5.5・§5.12・§5.13、
  [0003 一括作成](0003-bulk-create-notes.md)（`scripts/create_notes.py`。呼び出しは変えない）、
  SPEC §4「著者ノート」、`backend/app/author_store.py`
- 分け方は [0006](0006-katakana-split-and-publisher-notes.md) で変更（2026-10-15）

## 2. 背景と目的

ユーザーの言葉:

> 著者を区切っている記号は "," 、"・" があって、著者と出版社が併記されている。ところどころ名前の一部に "・" が
> 含まれているところもあるがしょうがないので名前を分割してしまってもいい。

いまの規則（0002）は著者欄を `,` `、` でしか分けない。このため次の2つが起きている。

1. `熊野純彦・大澤真幸` のように `・` で並べた2人が、1人の著者（1つの著者ノート）になる。
2. 出版社の名前が著者になる（`茸本朗, HS` の `HS`、著者欄が `学研プラス` だけの本）。著者ノート `学研プラス.md` ができる。

ユーザーは既に自分の PC で `scripts/create_notes.py` を流し、本棚の全部の著者のノートを作っている（「うまく動いていそう」）。
だから、**旧い規則で作られたノート（`ダニエル・L・エヴェレット.md`、`学研プラス.md` など）がある状態で、
重複ノートを作らず、既存のファイルを変えずに**新しい規則へ移ることが要る。

## 3. 決定

1. **著者欄を括弧の外の `,` `、` `・` で分ける**（NFKC のあとに分けるので `，` `､` `･` もそれぞれ `,` `、` `・` として分かれる）。
   `＝`（NFKC で `=`）と `·`（U+00B7）は区切りにしない。括弧の中では分けない・役割表記を落とす・分けた名前を通し直しても
   変わらない（冪等）、はいまのまま。役割の並び（`(著, 編集)`）の区切りにも `・` を含め、`（著・編）` も丸ごと役割として落とす。
2. **名前の一部の `・` でも分ける**（`ダニエル・L・エヴェレット` → `ダニエル` と `エヴェレット`。ユーザーが了承）。
3. **英字1文字のイニシャルは名前にしない**。分けて役割を落とした名前の照合キーが ASCII の英字1文字（`[a-z]` に一致）なら捨てる
   （`L` `L.` `Ｌ` `h`）。漢字・かな1文字（`楊` `文`）、英字2文字以上（`HS`）、つないだイニシャル（`J.K.ローリング`）は残す。
   これは `split_authors` の中で行うので、DB 側（著者欄）とノート側（ファイル名・aliases）の両方に効く。
4. **出版社の名前を著者にしない**（`collect_authors` だけで行う）。比べる出版社は**渡された全部の本の出版社欄**の、
   文字列全体の照合キー（`author_key(publisher)`。株式会社などは落とさない）。空・null の出版社欄は比べない。
   1冊の著者欄の中で、**隣り合う1つ以上の名前のキーをつないだもの**が出版社のキーと一致したら、その名前をまとめて落とす
   （`・` を含む出版社名 `ディスカヴァー・トゥエンティワン` は決定1で2つに分かれるが、つないだキーは出版社欄のキーと同じになる）。
   `collect_authors(books)` のシグネチャは変えない（出版社の集合は渡された `books` から作る）。
5. **ノートが集める名前（`note_names`）には出版社の除外を効かせない**。分け方（決定1〜3）は効く。
6. **照合キー（`author_key`）は変えない**。`_KEY_DROP` の `・` は残す（理由は §5.4）。
7. **既存のノートは変更しない**（改名・分割・削除しない。マーカーの中の一覧だけ、これまでどおり書き直す）。旧い規則の
   `ダニエル・L・エヴェレット.md` は、ファイル名が新しい規則で `ダニエル` `エヴェレット` に分かれるので、その両方を集めるノートになる。
   断片ごとの重複ノートは作らない（既存ノートが集めているキーは covered）。出版社の名前のノート（`学研プラス.md`）は
   「この名前の本はまだありません」になる。消すのはユーザー（アプリは作り直さない）。
8. 変えないもの: テーマノート（タグ）の規則、ウォッチャーの方針（著者ノートの自動作成はレポートのある著者だけ）、
   `scripts/create_notes.py` のコード、frontend・API・DB のスキーマ。

### 5.2 分け方（`split_authors`）

```python
_SEPARATOR_CHARS = ",、・"   # NFKC のあとに使う（，→ , ／ ､ → 、／ ･ → ・ は NFKC が揃える）。· (U+00B7) と = は区切りにしない
_INITIAL_KEY = re.compile(r"[a-z]")   # 照合キーが英字1文字の名前（L、L.、Ｌ）はイニシャル。名前にしない

def split_authors(author: Optional[str]) -> list[str]:
    """著者欄を人ごとの表示名に分ける。キーで重複を除き、出てきた順に返す。

    書式文字を除去 → NFKC → 括弧の外の `,` `、` `・` で分割 → 空白を1つに詰めて strip
    → 末尾の役割表記を繰り返し落とす。キーが空になるもの（空文字・役割だけ）と、キーが英字1文字のもの
    （`ダニエル・L・エヴェレット` の `L`）は捨てる。
    名前の一部の `・` でも分ける（`ダニエル・L・エヴェレット` → `ダニエル`, `エヴェレット`。0005）。
    結果の各名前をもう一度この関数に通しても変わらない（ノートの stem や aliases に使えるように）。
    """
    ...
    for part in _split_outside_brackets(_normalize(author)):
        name = _strip_roles(_SPACES.sub(" ", part).strip())
        key = author_key(name)
        if key and not _INITIAL_KEY.fullmatch(key) and key not in seen:
            seen.add(key)
            names.append(name)
```

規則の細部:

- **区切り文字**: `,`（U+002C）・`、`（U+3001）・`・`（U+30FB）。NFKC で `，`（U+FF0C）→ `,`、`､`（U+FF64）→ `、`、
  `･`（U+FF65）→ `・` になるので、これらも区切り（Python で `unicodedata.normalize("NFKC", "，､･")` → `",、・"` を確認）。
  `＝`/`=`、`·`（U+00B7）、`‧`、`／` は区切りにしない（`／` で並べた2人は 0002 §9 のまま未決）。
- **括弧の中**: `(…)` `[…]`（NFKC で全角の `（）［］` もこれになる）の中の `・` では分けない。括弧の中が役割の語だけ
  （`著・編集`、`著, 編`、`編著`）なら括弧ごと落とす（`_ROLE_LIST` の区切りに `・` が入るため）。役割でない語が混ざる括弧
  （`山田 (東京・大阪)`）は名前の一部として残す。閉じていない括弧は無視する（いまと同じ）。
- **役割表記との順序**: 先に分けて、断片ごとに役割を落とす。`山田太郎 著・鈴木花子 訳` → `山田太郎`, `鈴木花子`。
  区切りの直後が役割の語だけの断片（`山田太郎 著・編` の `編`）は落とさず、名前として残る（§9）。
- **イニシャル**: 役割を落としたあとの名前の `author_key` が `[a-z]` に `fullmatch` するもの。キーは空白・`.`・`・`・`=`・`·` を
  除き casefold したものなので、`L` `L.` `Ｌ`（NFKC で `L`）` l ` が当たる。ASCII の英字だけを見る（`é` などは残す）。
  当たらないもの: `HS`（2文字）、`J.K.ローリング`（`・` で分けていない。キー `jkローリング`）、`Jr.`（キー `jr`）、`楊`、`文`、`7`。
- **名前が残らない場合**: 著者欄が `L`、`H・G`、`, ・ ,` のように捨てる名前だけなら `[]`。その本はどの著者にも入らない
  （著者欄が空の本と同じ。ノートにもハブにも出ない）。ノートの stem が `L` だけのような場合は、そのノートは何も集めない
  （§5.6）。
- **冪等性**: 分けた名前に括弧の外の `・` は残らず、イニシャルは結果に入らないので、`split_authors(", ".join(names)) == names`
  は保たれる（§5.8 の例すべてで確認）。

### 5.3 出版社の除外（`collect_authors`）

```python
def _publisher_keys(books: list[Book]) -> frozenset[str]:
    """本の出版社欄（文字列全体）の照合キー。null・空・キーが空になるもの（空白だけ）は入れない。"""
    return frozenset(key for key in (author_key(b.publisher) for b in books if b.publisher) if key)


def _drop_publishers(names: list[str], publishers: frozenset[str]) -> list[str]:
    """著者欄から分けた名前のうち、出版社の名前を落とす（出てきた順は保つ）。

    隣り合う1つ以上の名前のキーをつないだものが出版社のキーと一致したら、その名前をまとめて落とす。
    `ディスカヴァー・トゥエンティワン` は `・` で2つに分かれるが、つないだキーは出版社欄のキー
    （author_key は `・` を除く）と同じになる。つないだ長さが出版社のキーの最長を超えたら打ち切る。
    """
    keys = [author_key(name) for name in names]
    longest = max(map(len, publishers), default=0)
    dropped: set[int] = set()
    for begin in range(len(keys)):
        joined = ""
        for end in range(begin, len(keys)):
            joined += keys[end]
            if len(joined) > longest:
                break
            if joined in publishers:
                dropped.update(range(begin, end + 1))
    return [name for i, name in enumerate(names) if i not in dropped]


def collect_authors(books: list[Book]) -> dict[str, Author]:
    """id 順に本を見て、`split_authors` の名前ごとに本を集める。キー → Author（出てきた順）。

    出版社の名前は著者にしない（`_drop_publishers`）。比べる出版社は、渡された本すべての出版社欄
    （呼び出し側は本棚の全部の本を渡す。rebuild と scripts/create_notes.py はそうしている）。
    著者欄が null・空・区切りだけ・捨てる名前（イニシャル・出版社）だけの本は、どの著者にも入らない。
    """
    publishers = _publisher_keys(books)
    ...
    for book in sorted(books, key=lambda b: b.id):
        for name in _drop_publishers(split_authors(book.author), publishers):
            ...（いまと同じ）
```

規則の細部:

- **どの出版社と比べるか**: その本の出版社だけでなく、**渡された全部の本の出版社**。`茸本朗, HS` の本の出版社欄が空でも、
  別の本の出版社欄が `HS` なら `HS` は著者にならない。全体で1つの集合なので、1語の出版社名（`学研プラス`）はどの本でも著者に
  ならない。
- **比べ方**: 出版社欄は**文字列全体**を `author_key` にする（分けない。`株式会社` `(株)` なども落とさない）。著者側は
  1つの名前、または同じ本の中で隣り合う名前の並びのキーをつないだもの。どちらも完全一致。出版社名の一部だけの名前
  （出版社欄 `ディスカヴァー・トゥエンティワン` に対する著者 `ディスカヴァー`）は落とさない。
- **空の出版社**: `None`・`""`・空白だけは集合に入れない（空のキーで何かを落とすことはない）。
- **計算量**: 1冊の名前の数を n、出版社のキーの最長を L とすると O(n·min(n, L))。著者欄は数十文字なので n は小さく、
  5秒ごとの rebuild でも問題にならない。`note_names`（aliases は長いことがある）は通らない。
- **`Author.name`**（表示名）は、除外のあとに残った名前のうち、そのキーを最初に持つ本の表記（いまと同じ）。

**なぜ `collect_authors` で除外し、`note_names` には効かせないか**

- 除外したい場所は「どの本がどの著者に入るか」（DB 側）だけ。除外した名前の `Author` は無いので、ノートがその名前を
  集めていても載る本は無い。ノート側で落としても、載る本は変わらない。
- ノートの名前は、ユーザーが意図して付けた名前（ファイル名・aliases）。勝手に捨てると、ノートの
  「集める名前: …」から消え、なぜ本が載らないかが見えなくなる。残しておけば「この名前の本はまだありません
  （集める名前: 学研プラス）」と理由が見える。
- `note_names(meta, stem)` を DB に依存させない。いまは純粋関数で、`plan_new_notes` は「雛形を読み直して自分の著者を集めるか」を
  これで確かめている。出版社の集合（本の追加で変わる）に依存させると、本を1冊足しただけでノートの covered が変わり、
  作り直しや「見分けがつかない」の判定が揺れる。

### 5.4 照合キー（`author_key`）の `・` は残す

`_KEY_DROP = re.compile(r"[\s・.=·]")` は変えない。理由:

- 分けたあとの名前（DB 側も、`note_names` を通したノート側も）には、括弧の外の `・` が残らない。キーから `・` を除くか
  どうかで結果が変わるのは、括弧の中の `・`（`山田 (東京・大阪)`）と、`split_authors` を通さずに `author_key` を
  直接かける文字列だけ。
- その直接かける文字列が**出版社欄**。`ディスカヴァー・トゥエンティワン` のキーが `ディスカヴァートゥエンティワン` になるので、
  §5.3 の「隣り合う名前のキーをつないだもの」と一致する。`・` を残すと一致しなくなり、`・` を含む出版社名は外れない。
- ユーザーが stem や aliases に `・` 入りの名前を書いても、`note_names` が `split_authors` で分けるので、`・` 入りのまま
  照合されることは無い。`・` を除かないことにしても、ここで救えるものは無い（§9 の「1つに戻す手段」は別の仕組みが要る）。
- 変えるとテスト（`TestAuthorKey` の `・` の組）と 0002 の説明を直す差分だけが増える。

### 5.5 ノート側（`note_names`。コードは変えない）

`note_names` はもともと stem と aliases を `split_authors` に通している。だから決定1〜3がそのまま効き、決定4（出版社）は効かない。

| `ダニエル・L・エヴェレット.md` | `ダニエル・L・エヴェレット` | `ダニエル`、`エヴェレット` |
| `H・G・ウェルズ.md` | `H・G・ウェルズ` | `ウェルズ` |

| `H.G. Wells.md`（`aliases: [H・G・ウェルズ]`） | `H.G. Wells`、`H・G・ウェルズ` | `H.G. Wells`、`ウェルズ` |

### 5.6 既存のノートへの影響

前提: ユーザーは旧い規則で `scripts/create_notes.py --apply` を流し、本棚の全部の著者のノートがある。ノートのファイルは
改名・分割・削除しない。書き直すのはマーカーの中（「集める名前」のコメント行と一覧）だけで、中身が変わったノートだけ
（いまと同じ `update_file` の規則。直近に編集したノートは飛ばす）。

| 既存のノート（でき方） | 0005 の後に載る本 | ハブ（著者一覧） | ファイル |
|---|---|---|---|
| `ダニエル・L・エヴェレット.md`（自動・一括） | 変わらない（`ダニエル` か `エヴェレット` を持つ本） | 「著者ノート」に同じ冊数で残る | 「集める名前: ダニエル、エヴェレット」に変わるので、マーカー内が1回だけ書き直される。`ダニエル.md`・`エヴェレット.md` は作らない |
| `H・G・ウェルズ.md`（自動・一括） | 変わらない（`ウェルズ` を持つ本） | 同上 | 同上（「集める名前: ウェルズ」）。`H.md`・`G.md` は作らない |
| `学研プラス.md`（一括。著者欄も出版社欄も `学研プラス`） | 無くなる。「この名前の本はまだありません（集める名前: 学研プラス）」 | 「著者ノート」に `0冊（レポート 0）` で残る。「ノートの無い著者」にも出ない | ユーザーが消す。消してもアプリ・スクリプトは作り直さない（もう著者ではない） |

### 5.7 既知の挙動（ユーザーが了承した「名前を分けてよい」の帰結）

- **同じ名を持つ別人が、同じ著者として混ざる**。`マイケル・サンデル.md` があるところに `マイケル・ルイス` の本（レポートあり）を足すと、
  `マイケル` は `マイケル・サンデル.md` が集めているので、その本は**サンデルのノートにも載り**、`ルイス.md` が新しく作られる
  （`ルイス・ダートネル.md` があれば、そちらにも載る）。差し替えた規則で実行して確かめた。ハブの冊数も混ざった数になる。
- **これから足すカナ名の著者は、名と姓が別の著者になる**。旧いノートが無い `ジョン・スミス`（レポートあり）からは `ジョン.md` と
  `スミス.md` が自動で作られる（`create_notes.py` も同じ）。
- **aliases でも1つに戻せない**。aliases も `split_authors` で分けるので、`マイケル・サンデル` という1つのキーは作れない（§9）。
- `DIAMONDハーバード・ビジネス・レビュー編集部` のような `・` を含む団体名も3つ（`DIAMONDハーバード`・`ビジネス`・`レビュー編集部`）に
  分かれる。出版社欄（`ダイヤモンド社`）とは一致しないので外れない。
- **出版社欄と同じ名前の個人**（自費出版で出版社欄が著者名）も著者から外れる。外させない手段は無い（§9）。

## 6. 選ばなかった案と理由

- **カナにはさまれた `・` は分けない（漢字の名前の間の `・` だけ分ける）**: 外国人名を保てるが、カナ名の2人を `・` で並べた
  著者欄を1人にしてしまい、判定の規則が増える。ユーザーが「名前を分割してしまってもいい」と了承しているので、単純な規則にする。
  同じ名の別人が混ざる（§5.7）のが困ると分かったら、新しい番号で検討する。
- **出版社の除外を `note_names` にも効かせる**: 載る本は変わらず、ノートの名前が DB に依存して `plan_new_notes` の確認が揺れる（§5.3）。
- **出版社欄も `split_authors` で分け、断片ごとに外す**: `ダイヤモンド・ビッグ社` から `ダイヤモンド` が外れ、`ジャレド・ダイヤモンド` の
  `ダイヤモンド` まで消える。出版社名の一部と同じ人名を消さないため、出版社側は全体で比べ、著者側の並びをつなぐ。
- **`_KEY_DROP` から `・` を外す**: §5.4。`・` を含む出版社名が外れなくなる。
- **旧い規則のノートを改名・分割する移行スクリプト**: 「既存のファイルは変えない」（決定7）に反し、ユーザーが書いた本文の行き先を決められない。
  ノートはそのまま断片を集め、分けたいノートだけユーザーが消す。
- **漢字・かな1文字の断片も落とす**: `楊`・`文` のような1文字の名を消す（オーケストレーターの決定）。

### 7.2 デプロイと、ユーザーの PC での手順

DB の移行は無い。コードを入れて常駐を再起動するだけ。

```bash
cd ~/Notes
git pull
systemctl --user restart notes-web
```

- 再起動後の最初の回（5秒以内）に、名前の変わるノート（stem・aliases に `・` がある、出版社の名前）のマーカー内と、ハブが
  1回だけ書き直される。新しいノートは基本的に作られない（§5.6。実データでは未確認）。
- そのあと、ユーザーがすること（任意）:
  1. ハブ `著者一覧.md` の「著者ノート」で `0冊` のノートを見る。出版社の名前のノート（`学研プラス.md` など）は消してよい。
  2. `・` で2人を並べた旧いノート（`熊野純彦・大澤真幸.md` など）は、人ごとにしたければ消す。レポートのある人のノートは
     アプリが次の回に作る。残りは `.venv/bin/python scripts/create_notes.py 2>&1 | less`（下見）→ `--apply`。
  3. 消したノートに書いた本文があれば、先に残すほうのノートへ移す（アプリは本文を移さない）。
- `create_notes.py` をもう一度流してもよい。旧いノートが断片を集めているので、作るのは消したノートの分だけ。
  「著者 N 人」の数は分けた・外した後の人数になる。
